We see that the throughput peaks at 32 and 48 bytes, instead of at 0. Which actually means that we haven't been getting optimal performance previously! The explanation is that we are loading 32 bytes at a time (as the size of the ymm registers are 32 bytes/256 bits). Because of this, we need our pointer into the vector to be aligned to 32 bytes. However, we are instead only aligned to 16 bytes. As I understand, some other programming languages also guarantee alignment to higher values (probably why Casey is aligned) but Rust doesn't. And I think the reason Rust chose 16 bytes is that it's needed for some simd instructions. Anyway, if we were aligned initially, we would expect peaks at 0, 32, 64. However, since we are shifted by 16, we really have our peaks at 16, 48, 80
